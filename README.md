# Daily AI Infra

以真实工程问题和面试追问为入口，逐步建立 AI 训练与推理的全栈知识体系。每篇聚焦一个值得掌握的核心问题，从直觉、必要基础和手算示例出发，连接图解、实际源码、论文、运行实验与工程取舍。

这里的目标是让读者能够解释原理、读懂实现、完成练习，并在真实场景中判断优化是否适用。

起步阶段前 10 篇已完成。从 [Tensor 的 shape、stride 与连续性](wiki/2026/10/2026-10-22-tensor-shape-stride-contiguity/README.md) 开始，按 [Wiki 索引](wiki/index.md) 逐步学到广播、浮点数、GPU 执行、分块、融合与 Attention。每篇先走一个能手算的小例子，再读推导和源码。

- [每日任务说明](docs/AUTOMATION.md)：运行时间、归档方式和运行条件。

## 每篇会提供什么

1. 一个真实工作中会遇到的主问题，以及由浅入深的面试追问。
2. 从零开始的解释、必要公式和带具体数字的例子。
3. 能说明数据流、执行过程或内存布局的图解。
4. 对应版本的源码路径、关键函数及论文或官方文档证据。
5. 至少两道代码练习、完整答案、运行方法与验证结果。
6. 优化适用条件、代价、常见误区和技术审查记录。

## 内容组织

```text
wiki/
  index.md
  YYYY/MM/YYYY-MM-DD-topic/
    README.md             # 正文、问题链、图解与面试追问
    references.md         # 来源版本、阅读笔记、论断与证据的对应关系
    review.md             # 技术审查、教学审查、验证结果与限制
    code/                 # 练习、参考答案、必要测试与运行说明
    assets/               # 按需保存图源与导出图片
    evidence/             # 相关源码片段、论文阅读笔记与实验记录
drafts/                   # 尚未通过审查的内容，按需创建
templates/                # 正文、资料和审查记录模板
.cache/upstream/          # 本地上游源码缓存，不作为发布归档
```

正文和参考资料一起归档。阅读笔记、关键证据、源码版本和复现记录应在仓库内可查；篇幅较大的上游仓库只作本地缓存，论文原文按可获取与可再分发条件保存，未保存的原文须保留精确来源与说明。

工作日每天 11:00（北京时间）启动一次产出任务，完成审查后更新索引，并自动提交、推送至本私密仓库的 `main` 分支。日常同一日期最多发布一篇新文章；本次按用户要求集中完成前 10 篇的范围见 [任务说明](docs/BOOTSTRAP10.md)。后续根据前置知识和已发布内容推进。
