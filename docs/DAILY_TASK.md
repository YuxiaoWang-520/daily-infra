# 每日 Wiki 任务

在 `/Users/wangyuxiao/Documents/ChatGPT/daily-infra` 中，按照 `AGENTS.md`、`docs/EDITORIAL.md`、`ROADMAP.md` 和 `templates/` 的规范，完成并归档当天的一篇 AI Infra 中文知识 Wiki。目标读者从零开始学习，以面试官的问题链逐步成长为能解释原理、读懂代码、验证优化、处理真实问题的全栈工程师。

## 每次运行

1. 以 `Asia/Shanghai` 计算日期；仅周一至周五执行，不考虑节假日调休。检查仓库状态、`wiki/index.md`、已有文章与草稿；保护无关改动。当天已经发布则不重复产出。
2. 从前置知识最充分的下一题开始，选择一个有常见工程用途的核心问题。首次从 Tensor 的 shape、stride 与连续性开始。选题不限于现有路线，持续覆盖算子、编译与执行、训练并行、推理引擎、算法、内存、Cache、存储、网络、资源管理与可靠性。
3. 实际调研当日一手资料。涉及引擎必须 clone 或 fetch 对应官方最新源码，固定完整 commit，并读取实际调用路径。算法主题必须阅读原始论文并与实现核对。记录检索时间、版本、来源定位和适用条件；不得凭记忆声称最新，不得将主分支行为说成稳定发布行为。
4. 用正文模板写作：真实场景和结论开篇，从直觉、基础术语、具体数字示例到公式、图解和源码逐层深入，说明优化适用条件、代价、验证方法和常见误区。至少一幅有解释价值的图，并给出由浅入深的面试追问及参考回答。
5. 提供至少两道代码练习及完整详解答案、运行方法、验收条件与边界情况；运行基础答案并保存真实验证记录。尽量提供 CPU 可运行的入门练习，GPU 专属部分如实记录验证范围。不可自动安装或升级全局依赖，不能把未运行结果写成通过。
6. 用资料模板归档引用、阅读笔记、关键源码证据与论文笔记，给出固定 commit 的链接和准确章节／符号定位。原始资料按可获取与可再分发条件保存；未保存原文时说明原因。源码缓存放 `.cache/upstream/`，发布证据须留在当篇目录，不能只留外部链接。
7. 执行技术证据与教学表达两轮审查，修复问题，保存实际审查和复验记录，标明自审或独立审查。遵守代码语言对应的审查要求。核心证据缺失、基础答案未验证或有 CRITICAL／HIGH 问题时保存草稿并报告阻塞，不得宣称发布。
8. 审查通过后，将完整内容归档到 `wiki/YYYY/MM/YYYY-MM-DD-topic/`，更新 `wiki/index.md`，检查本篇链接、图源、题目、答案、资料和审查记录。每个上海日期最多一篇新文章；重复运行恢复同一篇，错过日期不集中补发。
9. 本任务授权本地 Wiki 文件产出与归档；不自动 commit、push、创建 PR、部署或对外发消息。

## 完成报告

成功时给出文章标题、核心问题、正文与练习的可点击本地链接、资料版本、验证摘要和下一篇候选题。失败时给出草稿位置、失败步骤、缺少的具体证据以及可继续工作的状态。不得把仅创建目录、只有提纲或未审查的正文报告为完成。

只有新文章完成、重要勘误、任务失败或需要用户处理时才报告；当天已经完成且没有重要变化时保持安静。
