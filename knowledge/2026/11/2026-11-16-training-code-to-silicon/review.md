# 审查记录

## 结论与范围

本按需专题经过主执行者的技术证据自审、教学表达自审，以及通用代理对本篇 `4` 个 Python 文件的独立代码审查。两轮自审分别包含公开材料与脱敏检查。当前没有未解决的 CRITICAL／HIGH 问题。

专题覆盖训练代码到设备执行的职责与接口，并给出自研可编程训练加速器的建议研发路线。9 层划分是教学组织方式。正文按需归档到知识区，原有日更索引与题目队列由日更流程维护。

## 第二轮，教学表达与脱敏自审

审查者为主执行者，日期为 `2026-11-16`。

- 主线从一个能够手算的 `C[0,0]` 和损失开始，依次说明 Tensor、求导、后端、代码生成、提交、驱动、设备控制及物理实现。
- 补充了 FP32 地址偏移与教学伪指令，让框架中的一个数值能对应到访存和乘加。补充硬件模块与软件契约表，说明矩阵单元之外还需实现哪些职责。
- 编译路径在职责图中单独连入运行路径，标出库预编译、可选图编译和 Driver API 直接调用。
- 正文就地解释核心术语，附术语表，指向已有张量、异步、GEMM、DDP、编译与 allocator 章节。
- `kernel` 的设备程序含义和 OS kernel 的含义在术语表中分别定义。
- 自研路线先给出目标程序与契约，再给并行研发和逐级验收，包含框架、工具、芯片及板卡，并明确所选产品边界。
- 两个动手追问附推导与步骤。取消输入梯度的行为标注为依赖分析预期，归档运行保持原始设置。
- 图与例子均为自编，来源无内部项目、数据、仓库、端点或生产观测。

图以 `3` 个 Mermaid 代码块与一致的 `.mmd` 图源交付，检查了节点、连线、顺序和说明，图源与正文逐字一致。
