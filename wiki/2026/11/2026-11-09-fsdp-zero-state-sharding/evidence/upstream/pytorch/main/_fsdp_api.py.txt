L00014 | @dataclass(frozen=True)
L00015 | class MixedPrecisionPolicy:
L00016 |     r"""
L00017 |     This configures FSDP's mixed precision. Unlike autocast, parameter casting
L00018 |     happens when parameters are all-gathered, while optional input and output
L00019 |     casting happens at module boundaries. This means low-precision activations
L00020 |     are saved for backward and high-to-low-precision casts are incurred only at
L00021 |     those boundaries.
L00022 | 
L00023 |     FSDP works well with module-level mixed precision since it keeps the
L00024 |     high-precision sharded parameters in memory anyway. In other words, FSDP
L00025 |     does not require any extra memory to keep a high-precision copy of the
L00026 |     parameters for the optimizer step.
L00027 | 
L00028 |     .. warning::
L00029 |         ``param_dtype_override_fn`` must return the same result for each logical parameter
L00030 |         on every rank. Rank-dependent results may cause ranks to build incompatible
L00031 |         collective buffers, which can fail or hang.
L00032 | 
L00033 |     Attributes:
L00034 |         param_dtype (Optional[torch.dtype]): This specifies the default dtype
L00035 |             for the unsharded parameters and hence the dtype for
L00036 |             forward/backward computation and the parameter all-gather. Forward
L00037 |             input casting also uses this dtype. If this is ``None``, then the
L00038 |             unsharded parameters use their original dtype. The optimizer step
L00039 |             uses the sharded parameters in the original dtype. (Default:
L00040 |             ``None``)
L00041 |         reduce_dtype (Optional[torch.dtype]): The dtype for gradient reduction
L00042 |             (reduce-scatter or all-reduce) and for accumulating gradients while
L00043 |             reduction is disabled via :meth:`FSDPModule.set_requires_gradient_sync`.
L00044 |             If ``None``, follows the parameter's ``grad_dtype`` configured before
L00045 |             lazy initialization (the first forward or :meth:`FSDPModule.unshard`):
L00046 |             unset uses the original parameter dtype;
L00047 |             explicit ``None`` accepts any incoming gradient dtype. This fallback
L00048 |             is independent of ``param_dtype``. Gradients with different dtypes
L00049 |             in one communication group are reduced in their promoted dtype
L00050 |             (e.g. fp32 for bf16 and fp32). Reduced shards retain the input
L00051 |             ``grad_dtype`` policy. (Default: ``None``)
L00052 | 
L00053 |             .. versionchanged:: 2.15
L00054 |                 With ``reduce_dtype=None``, gradients were previously reduced
L00055 |                 in ``param_dtype`` when it was set. They now follow the
L00056 |                 parameter's ``grad_dtype`` as described above, e.g. fp32 for fp32
L00057 |                 parameters with ``param_dtype=torch.bfloat16``. Set
L00058 |                 ``reduce_dtype=torch.bfloat16`` to keep the previous behavior.
L00059 |                 FSDP1 still reduces in ``param_dtype``.
L00060 |         output_dtype (Optional[torch.dtype]): This specifies the dtype for
L00061 |             casting floating-point forward outputs. This can be used to
L00062 |             help implement cases where different modules have different mixed
L00063 |             precision policies. (Default: ``None``)
L00064 |         cast_forward_inputs (bool): This specifies whether FSDP should cast the
L00065 |             forward's floating-point input tensors to ``param_dtype`` or not.
L00066 |             For grouped ``fully_shard([a, b, ...])``, the cast is applied per
L00067 |             module, before each module's forward.
L00068 |         param_dtype_override_fn (Optional[Callable[[nn.Parameter], Optional[torch.dtype]]]):
L00069 |             Optional per-parameter override for ``param_dtype``. The callable
L00070 |             is evaluated once for each managed parameter when FSDP is applied.
L00071 |             Returning the parameter's original dtype preserves that parameter
L00072 |             in its original dtype; returning ``None`` or ``param_dtype`` uses
L00073 |             the default ``param_dtype``. Other dtypes are not supported.
L00074 |             Forward input casting continues to use ``param_dtype``.
L00075 |             (Default: ``None``)
L00076 |     """
L00077 |
